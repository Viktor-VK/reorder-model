# Reorder Model — тестовое задание Supply Chain Data Analyst (Генерация)

Модель рекомендуемого количества к заказу по 200 SKU на дату расчёта 19.09.2025, с бэктестом на исторических данных и сравнением с базовым вариантом.

## Методика (коротко, подробно — в ноутбуке)

- **Оценка спроса** — "дни защиты + страховой запас": среднесуточный спрос (с поправкой на дефицит) × protection period, плюс `z(Service Level) × эмпирическое std` скользящих сумм спроса за такие периоды. Не нормальная формула на сырых продажах — у 85% SKU сильно прерывистый спрос.
- **Поправка на дефицит** — 23,5% SKU-дней имеют наблюдаемый нулевой остаток, и продажи в такие дни в среднем в 4 раза ниже (censored demand); такие дни заменяются на среднее по SKU в дни с товаром в наличии.
- **Protection period** = срок поставки (10 дней) + интервал до следующего заказа из `OrderCalendar` — вычисляется на каждую дату, не захардкожен.
- **Поставки учитываются только если успевают прийти в protection period** — из 199 открытых поставок 59 (29,6%) прибывают позже горизонта и не засчитываются.
- **Service Level = 95%**, выбран по анализу чувствительности (90/95/98%) на данных, отдельных от итоговой проверки.
- **Бэктест** — 8 исторических контрольных дат, разделённых на 5 TUNE (подбор Service Level) и 3 TEST (итоговое сравнение с baseline) — не подбираем параметр и не проверяем результат на одних и тех же данных.
- 18 SKU без истории продаж за всё время — явно помечены в итоговой таблице, а не скрыты под нулевой рекомендацией.

## Ключевые результаты

- Финальная рекомендация: 200 SKU, суммарно **799 шт.** к заказу.
- Бэктест (TEST-даты): доработанная модель против baseline — **Cycle Service Level 95,2% → 97,3%**, **Fill Rate 80,6% → 89,6%**, ценой роста среднего запаса на 29% (13,1 → 16,9 шт.).
- Полный список допущений, ограничений и направлений развития — в финальных разделах ноутбука (2 и 3).

## Что где лежит

```
reorder-model/
  data/                     исходные данные (candidate_data.xlsx, data_dictionary.xlsx)
  notebooks/
    reorder_model.ipynb     основной артефакт: данные → EDA → baseline → бэктест → финальный расчёт

    RecommendedOrder.xlsx   финальная таблица SKU -> RecommendedOrder
  README.md                 этот файл
  requirements.txt          зависимости для запуска ноутбука
```

## Как запустить

```
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
jupyter notebook notebooks/reorder_model.ipynb
```

Либо пересчитать без интерфейса Jupyter:

```
jupyter nbconvert --to notebook --execute --inplace notebooks/reorder_model.ipynb
```
