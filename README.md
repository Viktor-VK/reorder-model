# Reorder Model — тестовое задание Supply Chain Data Analyst (Генерация)

Модель рекомендуемого количества к заказу по 200 SKU на дату расчёта 19.09.2025, с бэктестом на исторических данных и сравнением с базовым вариантом.

## Методика (коротко, подробно — в ноутбуке)

- **Оценка спроса** — эмпирический квантиль скользящих сумм продаж за protection period (не среднее, не нормальное распределение): у 85% SKU сильно прерывистый спрос, параметрические формулы для него не подходят.
- **Protection period** = срок поставки (10 дней) + интервал до следующего заказа из `OrderCalendar` — вычисляется на каждую дату, не захардкожен.
- **Service Level = 95%**, выбран по анализу чувствительности (90/95/98%) как точка, где выигрыш в сервисе ещё ощутимо опережает рост запаса.
- **Бэктест** — 8 исторических контрольных дат (08.08–03.09.2025), с явно зафиксированными допущениями (стартовый остаток из факта, спрос — только по данным до даты решения, без утечки будущего).
- 18 SKU без истории продаж за всё время — явно помечены в итоговой таблице, а не скрыты под нулевой рекомендацией.

## Ключевые результаты

- Финальная рекомендация: 200 SKU, суммарно **988 шт.** к заказу (для сравнения — простой baseline без страхового запаса дал бы 97 шт.).
- Бэктест: доработанная модель против baseline — **Cycle Service Level 95,1% → 98,0%**, **Fill Rate 85,2% → 93,5%**, ценой роста среднего запаса с 14,3 до 19,3 шт.
- Полный список допущений, ограничений и направлений развития — в финальных разделах ноутбука (2 и 3).

## Как запустить

```
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
jupyter notebook notebooks/reorder_model.ipynb
```

Либо пересчитать без интерфейса Jupyter:

```
jupyter nbconvert --to notebook --execute --inplace notebooks/reorder_model.ipynb
```
